## 1. 무슨 일이 있었나

`web/backend/singcup_sweep.py`(클립 하트/조회수 갱신)가 두 가지 결함으로
**사이클을 완주하지 못하고 좀비 상태로 굳는** 장애가 있었다. 두 결함은 독립이다.

### P0 — 토큰 버킷이 `rate < 1.0`에서 영구 대기 (커밋 `ebd7bb9`)

`TokenBucket.acquire()`가 토큰 **저장 용량**을 **충전 속도(rate)** 로 제한했다.

```python
self.tokens = min(self.rate, self.tokens + elapsed * self.rate)
```

요청 하나에 토큰 1개가 필요한데 rate가 1 미만이면 토큰이 rate에 수렴해 1.0에
영영 도달하지 못한다. `tokens=1.0`으로 시작해도 첫 계산에서 `min(0.749, 1.0+ε)`로
깎이므로 **첫 acquire부터** 멈춘다.

재현(수정 전): `rate=1.7` OK / `rate=1.0` OK(경계) / `rate=0.749` 정지 /
`rate=0.5`·`0.2` 영구 대기.

즉 **429나 카드 실패로 `slow_down(×0.5)`이 한 번이라도 발생하면 그 사이클이
첫 클립에서 통째로 멈췄다.** 운영 로그와 일치(`sweep_start rate_per_second=0.749`
→ 해당 run_id의 `sweep_done` 없음, `processed=0`이 25분 유지).

**수정:** 저장 용량과 충전 속도를 분리하고, 어떤 속도에서도 토큰 한 개는 모을 수
있도록 용량에 최소 1.0을 보장.

### P1 — DB 잠금이 스윕을 좀비로 만든 구조 (커밋 `1d1be0d`)

`02:35:09 sweep_loop_error(database is locked)` 이후 `sweep_done`도 `sweep_failed`도
남지 않는데 개별 클립 로그만 계속 찍히는 상태가 관측됐다. 경로:

1. `one()`이 `_apply_metrics`로 쓰기 트랜잭션을 열고
2. 커밋 없이 다음 클립의 토큰 대기 + 카드 API + 상세 API를 await
3. 25건마다 커밋 → 쓰기 잠금이 25~30초 유지
4. `busy_timeout`(10초) 초과 → 봇(`chzzk_chat`/monitor)과 `rising_collector`가 locked
5. 스윕 자신도 locked → `except` 진입
6. `except` 안의 `_progress`가 또 locked → `sweep_failed` 기록 전에 예외 재전파
7. `asyncio.gather`는 첫 예외로 완료하지만 남은 코루틴을 취소하지 않음 → **고아 워커**
8. 고아가 heartbeat를 갱신 → stale 판정 불가 → **새 사이클 영구 차단**
9. `recompute_ranking`·스냅샷·`sweep_done` 모두 미실행

실측: run `0f70033b`가 processed 300 → 4200까지 오르는 동안 `last_completed_run`은
계속 `null`.

**수정 요지**
- 네트워크와 DB 분리: 카드·상세를 먼저 다 받고 `_persist_clip`에서 열자마자 커밋.
  트랜잭션 30초 → 수 ms.
- `db_write()`: 잠금이면 지수 백오프+jitter 재시도, 매 시도마다 반드시 rollback,
  소진하면 예외 없이 `False`. 잠금이 아닌 오류는 그대로 전파.
- `one()`이 예외를 밖으로 내보내지 않고 `gather(return_exceptions=True)`로 모든
  태스크를 대기 → 고아 0. 취소 시에도 남은 태스크를 cancel+await.
- `_progress_safe()`: 상태 기록 실패가 스케줄러까지 전파되지 않음.
- `finally`에서 최종 상태와 `completed_at`을 반드시 남기고, 실패 시
  `final_status_persist_failed`를 로그로 남김.
- `reap_stale_runs()`: heartbeat 끊긴 running 행 정리. 스케줄러가 매 틱 호출해
  최종 상태 저장이 실패해도 새 사이클이 영구 차단되지 않게 한다.
- **클립 단위 락**(전역 락 미사용): 같은 `clip_uid` 지표를 고치는 모든 경로가
  DB named lock `singcup_clip:{uid}`를 공유 — 정기 스윕 / `refresh_metrics` /
  `refresh_one_clip` / `_scan_batch`(탐색·재시도·reconcile·백필) /
  `_register_from_card`(retag·rediscover). 전역 락을 한 사이클 내내 잡으면 그동안
  수동 조작이 전면 차단되므로 쓰지 않는다.
