# 싱드컵 '자유게시판 홍보글' API 참고 문서

작성: 2026-08-02 · 프론트 UI 제거 시점의 계약을 그대로 보존한다.

이 문서는 **프론트 drawer만 제거**하면서 남긴 기록이다. 백엔드 라우터·수집기·DB는
그대로 살아 있으므로, 나중에 비슷한 화면을 만들 때 여기서부터 시작하면 된다.

---

## 1. 기능 개요

싱드컵 페이지(`/stats` 의 싱드컵 탭)의 **보조 drawer**였다.

| 항목 | 값 |
|---|---|
| 버튼명 | `자유게시판 홍보글` |
| URL 상태 | `?view=board` |
| 열림 방식 | 데스크톱 = 우측 drawer, 모바일 = 전체 화면 |
| 닫기 | 배경 클릭 · X 버튼 · `Escape` |
| 호출 시점 | **drawer를 열 때 1회만** |
| 자동 폴링 | **없음** (`useEffect` 의존성 `[]`, `setInterval` 없음) |
| 재갱신 | 없음 — 닫았다 다시 열어야 새로 받는다 |
| 요청 취소 | 없음 (`AbortController` 미사용, `alive` 플래그로 setState만 차단) |
| 마지막 성공 시각 표시 | 없음 |

데이터 성격: 네이버 게임 '치지직 라운지' **자유게시판(boardId=4)** 에 올라온
`[싱드컵]` 말머리 게시글을 **버프 수 기준**으로 매긴 순위. 클립 하트 순위와는
완전히 다른 데이터다.

## 2. 기존 프론트 호출

```ts
// web/frontend/app/stats/Singcup.tsx  (BoardDrawer)
api.singcup.rankings(100)
```

```ts
// web/frontend/lib/api.ts
rankings: (limit = 200) =>
  fetch(`${BASE}/api/singcup/rankings?limit=${limit}`).then(r => r.json())
    as Promise<SingcupRankings>,
```

## 3. 실제 HTTP 계약

```http
GET /api/singcup/rankings?limit=100
```

| 항목 | 값 |
|---|---|
| 인증 | **없음** (공개 GET) |
| 필요한 헤더 | 없음 |
| `limit` 기본값 | 라우터 기본 `200`, 프론트 wrapper 기본 `200`, drawer는 `100`으로 호출 |
| `limit` 유효 범위 | 서버에서 `max(1, min(500, limit))`로 **클램프**. 500 초과·0·음수를 보내도 400이 아니라 조용히 보정된다 |
| 응답 캐시 | 라우터에 `Cache-Control` 지정 **없음**. `/api/singcup/main` 같은 모듈 캐시·ETag도 **없다** |
| rate limit | `rate_limit.py`의 **default 버킷**. `_is_heavy()` 대상이 아니다 |
| 오류 계약 | 수집이 실패해도 **DB의 마지막 정상 데이터를 그대로 반환한다.** 빈 목록을 내려 화면을 비우지 않는다. 신선도는 `collector.stale`로 알린다 |

## 5. 응답의 주요 필드

```
event      : { id, name, startAt, endAt, status }
summary    : submissionCount   제출 게시글 수
             participantCount  순위에 오른 참가자 수
             totalBuffCount    버프 합계
             topNickname       1위 닉네임 (없으면 null)
collector  : lastSuccessAt     마지막 성공 수집 시각 (ISO, KST)
             lastAttemptAt     마지막 시도 시각
             status            마지막 회차 상태 문자열
             stale             STALE_AFTER_MINUTES 초과 여부
             staleAfterMinutes 판정 기준(분)
rankings[] : rank, feedId, authorIdHash, authorNickname,
             authorProfileImageUrl, authorVerified, title,
             buffCount, nerfCount, viewCount, commentCount,
             createdAt, clipUrl, postUrl, mobilePostUrl
```

작성자 동일성 판정은 **`authorIdHash`** 로 한다. 닉네임은 바뀔 수 있으므로
닉네임으로 dedup하지 말 것 (수집기 쪽 규칙과 동일하다).

## 6. 재사용 시 주의점

### ⚠ `/rankings` 와 `/rankings-page` 는 **완전히 다른 API**다

| 경로 | 내용 |
|---|---|
| `GET /api/singcup/rankings` | **자유게시판 버프 순위** (이 문서의 대상). `singcup_feeds` 기반 |
| `GET /api/singcup/rankings-page` | **클립 하트 기반 참가자 랭킹**의 Split API 페이지. `singcup_clips` 기반 |

이름이 비슷해 헷갈리기 쉽다. `singcup_router.py`에도 "경로 이름이 `/rankings`가
아닌 이유"라는 주석이 그래서 붙어 있다. 새 화면을 만들 때 둘을 섞지 말 것.

### 호출 정책

- 과거 UI는 **drawer를 열 때만 1회** 호출했고 폴링하지 않았다.
- **새 기능에서 전체 데이터를 자동 폴링하지 말 것.** `/api/singcup/main`에서
  분당 63회 폴링이 Railway egress 월 $29.98로 추산된 전례가 있다
  (`CLAUDE.md` 참고). 이 응답도 참가자 수에 비례해 커진다.
- 갱신이 필요하면 `/api/singcup/main`이 쓰는 방식(모듈 캐시 + in-flight 합류 +
  visibility 기반 재검증)을 따르고, 컴포넌트에 `setInterval` + `fetch`를 새로
  만들지 말 것.
- `limit`을 필요 이상으로 키우지 말 것. 서버가 500에서 클램프한다.

### 개선 여지 (과거 UI의 약점)

- 마지막 성공 수집 시각(`collector.lastSuccessAt`)이 화면에 없어서, 사용자가
  목록이 몇 분 전 것인지 알 수 없었다. 새로 만들면 이걸 표시할 것.
- `AbortController`가 없어 drawer를 닫아도 요청이 계속됐다.
- `collector.stale`을 화면에 반영하지 않았다.

## 7. 제거 이유

- 싱드컵의 핵심(클립 하트 기반 순위)과 직접적인 관련성이 낮다.
- 상단 UI 복잡도를 줄인다.
- 쓰이지 않는 보조 API 호출을 없앤다.
- **백엔드 API는 유지한다** — 미래 참고와 다른 소비자 가능성 때문이다.
  수집기도 계속 돌고 `singcup_feeds` 데이터도 계속 쌓인다.
