> 이 문서는 프로젝트 전체(디스코드 봇 + 웹 대시보드 + 부가 서비스)의 **모든 페이지/기능과
> 그 기술 구현**을 한눈에 보기 위한 참조 문서입니다. 세션 작업 이력은 `CHANGELOG.md`,
> 개발 시 지켜야 할 규칙·주의사항은 `CLAUDE.md`를 보세요. 이 문서는 "무엇이 있고 어떻게

> **최신화 규칙**: 기능/페이지/엔드포인트/DB 스키마가 바뀌면 이 문서의 해당 표·항목을

## 0. 시스템 전체 구조

NexBot은 **독립적으로 실행되는 여러 서비스**로 구성된 모노레포입니다.

| 서비스 | 경로 | 실행 형태 | 역할 |
|--------|------|-----------|------|
| 디스코드 봇 | `main.py`, `cogs/`, `utils/` | discord.py 프로세스 | 슬래시 명령어, 이벤트, 백그라운드 루프 |
| 대시보드 API | `web/backend/` | FastAPI (별도 프로세스) | OAuth, 설정 CRUD, 공개/관리 API |
| 대시보드 UI | `web/frontend/` | Next.js (App Router) | 설정 페이지, 공개 페이지, 오버레이 |
| 릴레이 | `relay/relay.py` | 한국 IP 호스트 상주 프로세스 | 치지직 커뮤니티 API 폴링 → 웹훅 전송 |
| 모바일 앱 | `chzzk-repo/` | Expo/React Native | 초기 단계, 대시보드와 무관 |

**핵심 공유 상태**: 봇과 백엔드는 **동일한 SQLite 파일(`bot.db`, WAL 모드)**을 읽고 씁니다.
프로덕션(Railway)에서는 한 컨테이너 안에서 `start.sh`가 봇을 백그라운드로, 백엔드를
포그라운드(`$PORT`)로 실행합니다. 두 프로세스는 직접 호출이 불가능하므로, DB의 타임스탬프
컬럼(`bot_stats.refresh_requested_at`) 등을 **폴링 신호**로 삼아 통신합니다.

- 슬래시 명령어는 **글로벌로만 동기화**됩니다(`main.py setup_hook`). 서버별 복사본은 없음
  (오너 전용 `@봇 sync guild`는 로컬 테스트용, `@봇 clearguild`는 중복 정리용).
- 인증: 디스코드 OAuth → JWT(`Authorization` 헤더). 쿠키를 안 쓰므로 CORS `allow_origins=["*"]`.

## 1. 디스코드 봇 (cogs)

로드되는 cog는 `main.py`의 `COGS` 리스트로 관리(`welcome, leveling, moderation, points,
reaction_roles, chzzk, chzzk_chat, verification, sichham, info`). 새 cog는 여기 추가해야 로드됨.
`admin.py`/`help.py`는 리스트에 없음(현재 미로드).

### 1.1 봇 코어 (`main.py`)

- **인텐트**: `members`, `message_content`, `reactions` 활성화.
- **백그라운드 루프 3종**:
  - `update_stats` (30분): 서버 수/치지직 구독 수를 `bot_stats`에 기록 + presence("N개의 서버") 갱신.
  - `poll_manual_refresh` (10초): `bot_stats.refresh_requested_at`이 바뀌면 즉시 통계/presence 재계산 (nexadmin 새로고침 버튼 신호).
  - `reconcile_verifications` (6시간): 봇 오프라인 중 놓친 탈퇴자의 `chzzk_verifications` 잔여 행 정리.
- **이벤트**: `on_guild_remove` → 해당 길드 치지직 인증 삭제. `VerifyView`를 재시작 후에도 동작하도록 persistent view 등록.
- **에러 핸들러**: 권한 부족/쿨다운/봇 권한 부족 등을 한국어 ephemeral 메시지로 통일.

### 1.2 서버 관리 · 모더레이션 (`moderation.py`)

| 명령어 | 권한 | 기능 |
|--------|------|------|
| `/추방` | kick | 자기보다 높은 역할은 관리자만 가능 |
| `/차단` `/차단해제` | ban | 메시지 삭제 기간(0~7일) 옵션 |
| `/뮤트` `/뮤트해제` | moderate | 타임아웃 적용, `mutes` 테이블에 기록 |
| `/경고` `/경고내역` `/경고초기화` | manage_messages | `warnings` 누적 기록 |
| `/청소` | manage_messages | 최대 100개 일괄 삭제 |

- **Auto-Mod** (`on_message`): 관리자는 예외. ①금지어 필터(`guild_config.badwords` CSV), ②멘션 도배(≥5), ③동일 메시지 반복 스팸(5초 창 내 5회). 위반 시 삭제+자동 경고.
- **경고 임계값 자동 처리**: 경고 3회 → 10분 자동 뮤트(`WARN_MUTE_THRESHOLD`). `warn_kick_threshold`/`warn_ban_threshold` 도달 시 자동 추방/차단.
- **루프**: `check_unmutes`(30초, 만료 뮤트 해제), `cleanup_msg_cache`(1시간, 스팸 캐시 정리).

### 1.3 애정도(레벨링) (`leveling.py`)

- **XP 획득**: 메시지당 15 XP, 60초 쿨타임. 레벨 공식은 MEE6 근사(`5*L² + 50*L + 100`).
- **레벨업 처리**: `level_rewards`에 등록된 역할 자동 부여, 알림 채널 또는 DM(`levelup_dm`)으로 통지.
- **포인트 연동**: `guild_config.points_per_level`이 있으면 레벨업당 포인트 지급(`_award_level_points`).
- **외부 연동**: `add_xp()`는 치지직 출석체크 등 외부에서 XP를 주입하는 진입점.
- **명령어**: `/랭크`(진행 바 표시), `/리더보드`(상위 10), `/xp설정`(관리자).

### 1.4 포인트 · 상점 · 미션 · 도박 (`points.py`)

- **명령어**: `/포인트`, `/포인트순위`, `/포인트지급`(관리자), `/포인트상점`, `/미션불러오기`(관리자), `/포인트도박`·`/포인트도박종료`(관리자).
- **상점**: `ShopSelect` 드롭다운 → 상세 임베드 → `교환하기` 버튼. **구매는 단일 원자적 UPDATE**로 잔액 확인+차감(연타 TOCTOU 방지), 재고 마감 시 환불. persistent view 재등록.
- **미션**: `미션 참가 신청` 버튼 → `mission_completions`에 `pending` 등록 → 관리자 승인 시 포인트 지급.
- **포인트 도박(Discord Poll 기반)**:
  - `points_gambling_config`/`options`(대시보드에서 설정)를 읽어 `discord.Poll` 생성.
  - 정산은 **라운드 종료 시점 잔액 기준**(Poll은 사전 차감 불가) — 잔액 부족자는 조용히 제외.
  - 정산 트리거: `poll_result` 메시지 이벤트 + `reconcile_gambling_loop`(300초 안전망).
  - 승자/배당 계산은 `utils/gambling.py`의 `resolve_gambling_winner`/`calc_gambling_payout` 공유.
  - ~~⚠️ 알려진 버그: `_settle_poll_session` 결과 임베드에서 `pool` 미정의~~ → **2026-07-25 수정됨** (`pool = total_charged * bet_amount` 추가).

### 1.5 입장 인증 (`verification.py`)

- **두 방식**: ①단순 버튼 인증(`VerifyView`, persistent) — 역할 부여/회수. ②치지직 뷰어 인증(`use_chzzk_verification`) — `/verify` 웹페이지로 링크.
- **신규 입장**: `on_member_join` → 미인증 역할 자동 부여.
- **`/입장메시지설정`**: 대시보드 설정값으로 고정 임베드를 채널에 전송/수정(`verification_embed_msg_id` 재사용). 봇 역할 위치·권한 부족을 사용자 친화적으로 안내.

### 1.6 환영/작별 (`welcome.py`)

- `on_member_join`: 자동 역할 부여 + 환영 임베드(`{mention}/{username}/{server}` 치환).
- `on_member_remove`: **치지직 인증 즉시 삭제** + 작별 임베드.

### 1.7 리액션 역할 (`reaction_roles.py`)

- `/반응역할`·`/반응역할제거`·`/반응역할목록`. `on_raw_reaction_add/remove`로 역할 자동 부여/회수.

### 1.8 시청자 참여(시참) (`sichham.py`)

- **메모리 기반 세션**(DB 미사용, `_sessions` 딕셔너리, guild별).
- 시청자용: `/시참등록`·`/시참취소`·`/시참확인`·`/시참목록`.
- 관리자용: `/시참시작`(최대인원·조건)·`/시참종료`·`/시참호출`(n명)·`/시참건너뛰기`(노쇼).

### 1.9 정보/도움말 (`info.py`)

- `/핑`, `/봇정보`(서버·유저 수·초대 링크), `/도움말`(일반), `/도움말관리`(전체, 관리자).

### 1.10 치지직 방송 알림 (`chzzk.py`)

- **모니터링 루프**(`CHZZK_POLL_INTERVAL`, 기본 60초): `chzzk_subscriptions` 전체를 순회하며 비공식 API(`api.chzzk.naver.com`)로 라이브 상태 확인 → LIVE 시작/종료 시 알림 임베드 전송.
- **명령어**: `/팔로우불러오기`(저장된 팔로우 기간으로 티어 역할 재적용), `/치지직설정`(대시보드 링크), `/치지직설정불러오기`(채널 변경 드롭다운), `/치지직알림테스트`.
- 팔로우 티어: `chzzk_follow_roles`(개월 수 → 역할) 우선, 없으면 legacy `follow_role_1month/3month`.

### 1.11 치지직 실시간 채팅 (`chzzk_chat.py`) — 946줄, 가장 복잡

봇 프로세스에서 실행. **공식 Session API**를 `chzzkpy` 라이브러리로 구독(스트리머 OAuth 토큰 재사용).

- **동기화 루프**(`SYNC_INTERVAL_SECONDS=60`): `chat_enabled=1`인 구독을 SQL로 필터해 연결. 소켓 사망 감지가 없어 `Client._gateway[sid].is_connected`를 직접 peek해 강제 재연결.
- **채팅 명령어 체계**:
  - 커스텀: `chzzk_chat_commands` — `checkin`(guild당 1개, 포인트+XP 지급, 1일1회 `chzzk_checkin_log`), `reply`(guild당 최대 5개, 텍스트 응답). 트리거는 공백 불가, 예약어 충돌 불가(`chzzk_router._validate_trigger`).
  - **빌트인**(항상 활성): `포인트`(잔액), `도박`(채팅 도박 시작), `투표 <번호>`(즉시 차감·1인1표), `도박종료`(정산). `!도박`/`!도박종료`는 스트리머(`user_id==channel` 휴리스틱) 또는 매니저만.
- **채팅 도박**: `chzzk_gambling_sessions`(guild당 진행중 1개 — 부분 unique 인덱스로 레이스 차단) + `chzzk_gambling_votes`(1인1표). 배당 계산은 `utils/gambling.py` 공유. Poll 도박과 달리 **베팅 즉시 차감**.
- **웹 테스트 큐**(`chzzk_chat_test_queue`, `TEST_QUEUE_INTERVAL_SECONDS=2`): 라이브 방송 없이 대시보드에서 명령어 시뮬레이션. 실제 구독 중이면 `user_client` 재사용, 아니면 `_NullChatClient`. 실제 채팅과 동일한 `_process_message`로 처리.
- **디버그 로그**: `chzzk_chat_log`(guild당 최근 50개 in/out) → 대시보드에 표시.
- **마크 이벤트 채팅 명령어**: 활성 `mc_events`가 1개일 때 `!디버프지급`/`!버프지급`/`!랜덤아이템` 처리 → RCON 실행(1.13 참조).

### 1.12 유틸 (`utils/`)

- `checks.py`: `is_mod_or_admin`/`is_admin`/`member_is_mod_or_admin` — `guild_config.mod_role_id` + `mod_managers` 기반.
- `gambling.py`: 승자 결정·배당 계산(Poll 도박/채팅 도박 공유).
- `embeds.py`: `success`/`error`/`mod_log` 임베드 빌더.
- `mc_rcon.py`: 마인크래프트 RCON 명령 전송.

## 2. 웹 백엔드 (`web/backend/`, FastAPI)

`main.py`가 라우터 11개를 등록. lifespan에서 `init_db()` + `chzzk_monitor` 백그라운드 시작.
`auth.py`(OAuth/JWT), `deps.py`(권한 의존성), `chzzk_monitor.py`(콘텐츠 폴링).

### 2.1 엔드포인트 전체 목록

**인증 (`auth_router.py`)**
- `GET /api/auth/login` — OAuth 시작(state 발급)
- `GET|POST /api/auth/callback` — 코드 교환 → JWT (루트 `/auth/callback` 호환 라우트도 존재, JWT는 URL 프래그먼트로 전달)
- `GET /api/auth/me` — 현재 유저

**길드 (`guilds_router.py`)**
- `GET /api/guilds` — 유저 관리 길드 목록
- `GET /api/guilds/{id}/channels` · `/roles` · `/members/search`

**서버 설정 (`settings_router.py`)**
- `GET|PUT /api/settings/{guild_id}` — 일반 설정
- `.../level-rewards`(GET/POST/DELETE), `.../verification`(GET/PUT)
- `.../leaderboard`(GET/DELETE), `.../warnings`(GET/DELETE 여러 형태)
- `.../managers`(GET/POST/DELETE) — 매니저 관리

**포인트 (`points_router.py`)**
- `.../leaderboard`, `.../adjust`
- `.../missions`(CRUD), `.../submissions`(승인/거부)
- `.../shop/items`(CRUD), `.../shop/exchanges`(목록, 사용 처리)
- `.../gambling`(GET/PUT) — 도박 설정

**치지직 (`chzzk_router.py`, 1067줄)**
- 검색: `GET /api/chzzk/search`
- 구독: `.../subscriptions`(GET/POST/PATCH/DELETE)
- 팔로워 역할: `.../follower-roles`(GET/PUT), `.../follow-tiers`(GET/POST/DELETE)
- 인증 목록: `.../verifications`
- 콘텐츠 알림: `.../content-notify`(GET/PUT)
- 채팅 명령어: `.../chat-commands`(CRUD), `.../chat-status`, `.../chat-log`, `.../chat-test`
- 오버레이: `.../overlay-token`(GET/regenerate), **공개** `GET /api/chzzk/overlay/{token}/gambling-status`·`/missions-status`
- 마크 이벤트: `.../mc-event`(GET/PUT)
- 디버그: `/api/chzzk/debug/*`

**치지직 OAuth (`chzzk_auth_router.py`, 660줄)**
- 스트리머: `GET /streamer-login-url` → `/callback`(플로우 1, 토큰 저장)
- 뷰어: `GET /login-url` → `/callback`(플로우 2, `discord↔chzzk` 매핑)
- 중복 등록 방지: 같은 chzzk 채널이 다른 길드에 스트리머 등록돼 있으면 `error=chzzk_already_registered` 리다이렉트.

**뷰어 인증 (`verify_router.py`)**: `GET /{guild_id}/status`, `POST /{guild_id}`

**관리자/nexadmin (`admin_router.py`, 515줄, 오너 전용)**
- `overview`, `refresh`, `guilds`, `chzzk`, `verifications`(GET/DELETE), `follow-stats`
- `chzzk/search`·`chzzk`(POST)·`chzzk/{sub_id}`(DELETE), `guilds/{id}`, `guilds/{id}/leave`
- `announcement`(GET/PUT) — 사이트 공지
- 성능: `_guild_member_map()`으로 길드당 멤버 1회 조회(120초 캐시). `_bot_guilds()`도 캐시.

**마크 이벤트 (`mc_event_router.py`, 오너 전용)**
- 이벤트 CRUD + `test`/`run`(RCON 실행)
- `guilds`(참가 서버·인게임 이름), `commands`(트리거), `items`(디버프/버프/랜덤 아이템), `purchases`(구매 이력)

**커뮤니티 (제거됨, 2026-07-25)** — `community_router.py`·`/community` 페이지·대시보드 토글·`api.community`를 모두 제거. `community_listing` 테이블만 `db.py`에 dormant 상태로 남음(append-only, drop 안 함). 치지직 **커뮤니티 글 알림**(`notify_community`)은 별개 기능으로 유지.

**통계 (`stats_router.py`)**: `GET /api/stats`, `/announcement`, `POST /visit`(일일 방문자 IP 해시)

### 2.3 CHZZK Rising 분석 (신규 · Phase 1, 2026-07-25~)

치지직 라이징/중소형 방송 트렌드 분석 서비스. **기획 전체는 2트랙(공개 포털 + 개인 대시보드)이며 현재 Phase 1(데이터 기반)만 구현됨.**

- **수집기** (`web/backend/rising_collector.py`) — 백엔드 lifespan의 asyncio 태스크. `api.chzzk.naver.com/service/v1/lives`를 커서 페이지네이션으로 순회해 전체 라이브 목록을 `RISING_COLLECT_INTERVAL`(기본 600초)마다 스냅샷. **Railway에서 실행 시도**(봇 monitor_loop이 이미 Railway에서 치지직 API를 쓰므로 가능성 높음) — 지역차단/실패 시 `rising_collect_runs.ok=0`+사유 기록 → 그때 relay처럼 Korea VM로 이전.
- **DB** — `rising_live_snapshots`(원천 시계열: 사이클별 라이브 1건=1행), `rising_collect_runs`(사이클 메타/헬스체크). 원천은 `RISING_RAW_RETENTION_DAYS`(기본 14일) 초과분 매 사이클 정리.
- **공개 API** (`routers/rising_router.py`, 인증 없음): `GET /api/rising/status`(수집기 헬스체크), `/overview`(최신 사이클: 체급분포 + 블루오션 게임 TOP10 + 요약), `/rising-stars`(24h 대비 성장률 상위, 데이터 부족 시 빈 목록).
- **핵심 지표**: 블루오션 지수 = 카테고리 시청자합/방송수(방송 3개 미만 제외), 체급 = 동시시청자 1000+/100~999/1~99.
- **Track A 공개 포털 (`app/stats/page.tsx`, 라우트 `/stats` "치지직 통계")** — 소프트콘 뷰어십 참고, **탭(개요/랭킹/카테고리) + 실시간 랭킹 테이블 중심** 레이아웃. 다크 + **2톤 그라데이션(그린 #00FFA3 → 시안 #00C2FF)**.
  - **개요 탭**: 요약 카드(직전 수집 대비 증감 ▲▼) + **시계열 꺾은선 차트**(`app/stats/LineChart.tsx`, 의존성 없이 SVG — 호버 크로스헤어+툴팁, 그라데이션 스트로크): 전체 시청자 추이(단일) + 체급별 방송 수 추이(3선) + 급상승 컴팩트.
  - **랭킹 탭**: 실시간 방송 랭킹 테이블 — 정렬(시청자/팔로워/방송시간)·검색·더보기. 방송시간은 open_date(KST)로 프론트 계산.
  - **카테고리 탭**: 게임별 시청자/방송수/방송당평균 테이블 + 시청자 막대.
  - 백엔드 엔드포인트 추가: `/api/rising/timeseries`(시각별 체급·총량), `/live-ranking`, `/categories`. QA 12항목 통과.
- **미구현(다음 단계)**: 시간대 히트맵, 통합 검색(현재 랭킹 탭 내 검색만), Track B(디스코드 로그인 개인 대시보드·AI 피드백·전략 추천). `/stats`는 client 컴포넌트라 크롤러가 로딩 셸을 봄 → AdSense엔 SSR 전환이 이상적(후속).
- **주의**: 성장률·히트맵·라이징은 **시계열이 쌓여야** 의미가 생김(수집 시작 후 최소 24시간~수일). 배포 직후엔 `/overview`(체급·틈새)만 즉시 채워지고 `/rising-stars`는 24h 후부터.
